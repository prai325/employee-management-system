FastAPI (Waiter): Celery Worker (Chef): Message Broker - Redis/RabbitMQ (Order Slip):

Celery me Redis ke 2 main kaam hote hain:1. Message Broker (As a Postman 📬)
   FastAPI aur Celery do alag-alag processes hain. FastAPI Celery ko direct order nahi de sakta.Jab aap FastAPI me my_task.delay() likhte hain, toh FastAPI us task ki details (jaise task ka naam aur uske arguments) ek message bana kar Redis ke andar daal deta hai.Celery Workers lagaatar Redis par nazar rakhte hain. Jaise hi Redis me koi naya task aata hai, Celery Worker use wahan se uthata hai aur execute (run) kar deta hai.

2. Result Backend (As a Notebook 📝)
   Jab Celery background me apna kaam poora kar leta hai (for example, heavy calculation ya email  send karna), toh uska jo output ya status hota hai (Success, Failed, ya koi data), use woh Redis me save kar deta hai.Agar baad me FastAPI ko check karna ho ki "Bhai, us task ka kya hua? Kaam khatam hua ya nahi?", toh FastAPI Redis se puch kar status pata kar sakta hai.

Ek simple real-life example se samjhein 🥪
   Maan lijiye aap ek restaurant me hain:Aap (FastAPI): Aapne order diya (Task trigger kiya).Waiter (Redis Broker): Waiter ne aapka order ek parchi (Kajag) par likha aur use kitchen ki window par chipka diya. Redis yahan wahi window hai jahan orders store hote hain temporary time ke liye.Chef (Celery Worker): Chef ne window se parchi uthayi aur khana banana shuru kar diya.Agar Redis nahi hoga, toh FastAPI Celery ko bata hi nahi payega ki background me kaun sa kaam karna hai.

What is IAM?

Answer:

IAM stands for Identity and Access Management. It is an AWS service used to securely manage identities and control access to AWS resources through users, groups, roles and policies.

What is an IAM User?

An IAM User represents an individual identity that can authenticate and access AWS resources according to its assigned permissions.

What is an IAM Group?

An IAM Group is a collection of IAM users to which common permissions can be assigned.

What is an IAM Policy?

An IAM Policy is a JSON-based document that defines what actions are allowed or denied on specific AWS resources.

What is an IAM Role?

An IAM Role is an identity with permissions that can be assumed by trusted entities such as AWS services, applications, or users.

User vs Role?
IAM User
→ Usually represents an individual identity.

IAM Role
→ Used to provide permissions that can be assumed
  by trusted entities.

What is Least Privilege?

Least privilege means giving an identity only the minimum permissions required to perform its job.

Q1. What is an IAM Policy?

An IAM Policy is a JSON document that defines permissions for AWS resources, including which actions are allowed or denied.

Q2. What is Effect?

Effect specifies whether an action is allowed or denied.

Q3. What is Action?

Action specifies the AWS operation that an identity is allowed or denied to perform.

Example:

s3:GetObject
s3:PutObject
Q4. What is Resource?

Resource specifies the AWS resource on which the policy applies.

Q5. What is Principal?

Principal identifies the entity that is allowed or trusted in a resource-based or trust policy.

Q6. What happens if one policy allows an action and another explicitly denies it?

Explicit Deny takes precedence over Allow.

Q7. What is the principle of least privilege?

Give an identity only the minimum permissions required to perform its task.
